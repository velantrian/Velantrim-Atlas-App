# 🧭 Routing Map

## Core decision rule

When a question uses the broad term `cognition`, do not route directly to Mentaury Soul without first identifying the intended scope.

```text
COGNITION QUESTION
      │
      ├─ general / substrate-neutral cognitive function
      │      → 🧠 Unified Cognitive System Architecture
      │
      └─ claims / beliefs / identity / relationships / commitments
             → 🌀 Mentaury Soul
```

## Primary routes

### 🧠 Unified Cognitive System Architecture

Route here for questions about the general functional organization of cognition independent of a particular modern implementation stack.

Examples:

- perception / representational availability;
- understanding;
- memory / experience as cognitive function;
- endogenous cognition;
- focus entry, maintenance and exit;
- valuation / affect as a research dimension;
- motivation / goal direction;
- self-related processing at the neutral architectural level;
- agency / endorsement / goal adoption;
- authorization as a distinct cognitive/decision boundary;
- action and consequences;
- continuity / revision;
- relations among these dimensions;
- substrate neutrality of the architecture.

Do not infer that this destination is a runtime module, Canon root, LLM architecture, RAG architecture or implementation owner.

### 🌀 Mentaury Soul

Route here for the owner-local cognition / identity domain.

Examples:

- claims and beliefs;
- belief/claim separation;
- self / non-self;
- identity continuity;
- relationships;
- commitments;
- character / person-local semantics;
- bounded cognition state owned by Soul.

Do not use Soul as the default owner of all cognition questions.

### 💠 Crystal

Route here for trusted memory/evidence concerns:

- evidence and provenance;
- trusted memory;
- claims as evidence-bearing records;
- bounded Canon admission;
- write boundaries;
- receipts and integrity.

### 🧬 Native Kernel

Route here for substrate-neutral semantic laws and invariants:

- meaning of shared terms;
- semantic portability;
- provenance obligations;
- uncertainty / revision semantics;
- declared loss;
- architecture-level semantic constraints.

### 🪁 Mentaury Kernel

Route here for cross-domain composition:

- compatibility;
- provenance across boundaries;
- declared loss during composition;
- non-escalation;
- Native ↔ Soul / cross-domain transport contracts.

### 🗿 Titan

Route here for orchestration / integration / bounded execution:

- providers and models;
- tools;
- runtime research;
- capability lifecycle;
- adapters;
- bounded execution and integration infrastructure.

### 🌎 Continuum

Route here for functional process continuity across lost or replaced inference/context/runtime:

- capture;
- handoff;
- transfer;
- rehydration;
- process state;
- continuity evidence.

### 🚀 Cognitive OS

Route here for model/reasoning/tool selection and assurance research:

- model roles;
- reasoning routing;
- capability planes;
- assurance;
- anti-degradation;
- model-composition research.

### ⚗️ CLOS

Route here for the broader research blueprint around substrate-neutral cognitive-life functions, states, transitions, competing formulations and bounded research candidates.

Do not use a CLOS research candidate as proof that the Unified Cognitive System Architecture has adopted a mandatory center, module or mechanism.

### 🧠 System OS

Route here for ecosystem-level system orientation: how independent projects relate, not for ownership of the underlying domain truth.

## Ambiguity rule

If a query materially overlaps more than one route, the Atlas should expose the distinction rather than collapse it.

```text
AMBIGUOUS ROUTE ≠ PERMISSION TO PICK THE BROADEST OWNER
OVERLAP ≠ SHARED OWNERSHIP
```
