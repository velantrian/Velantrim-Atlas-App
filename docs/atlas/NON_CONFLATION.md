# 🛡️ Non-Conflation Rules

The Atlas exists to preserve distinctions while helping users and AI navigate the ecosystem.

## Core invariants

```text
UNIFIED COGNITIVE ARCHITECTURE ≠ MENTAURY SOUL
NEUTRAL COGNITIVE FUNCTION ≠ PROJECT-LOCAL COGNITIVE OWNERSHIP
RESEARCH DIMENSION ≠ RUNTIME MODULE
ARCHITECTURAL ORIENTATION ≠ OWNER AUTHORITY
ATLAS ROUTE ≠ DOMAIN TRUTH
ATLAS POINTER ≠ OWNERSHIP
ATLAS INDEX ≠ CANON
NAVIGATION FIX ≠ ARCHITECTURE REDESIGN
```

## Global ecosystem boundaries

```text
RESEARCH ≠ RUNTIME
SPEC ≠ IMPLEMENTATION
RETRIEVAL ≠ EVIDENCE
CLAIM ≠ BELIEF
EVIDENCE ≠ IDENTITY
IDENTITY ≠ AUTHORITY
CAPABILITY ≠ PERMISSION
MODEL OUTPUT ≠ CANON
CI GREEN ≠ PRODUCTION AUTHORIZATION
```

## Technology neutrality

A route to a cognitive architecture does not define that architecture in terms of the technologies currently used to implement AI systems.

```text
COGNITIVE FUNCTION ≠ CURRENT DIGITAL IMPLEMENTATION
LLM ≠ COGNITIVE ARCHITECTURE
RAG ≠ COGNITIVE ARCHITECTURE
GRAPH ≠ COGNITIVE ARCHITECTURE
DATABASE ≠ COGNITIVE ARCHITECTURE
```

A modern technology may be a possible implementation substrate without becoming part of the architectural definition.

## Donor boundary

Human, animal, neuroscience, psychology, philosophy or other comparative sources may contribute phenomena, distinctions, counterexamples and questions.

```text
DONOR ≠ ARCHITECTURE
BIOLOGICAL PHENOMENON ≠ DIGITAL REQUIREMENT
PHENOMENOLOGICAL ANALOGY ≠ ESTABLISHED MECHANISM
```

## Routing overlap

If two domains overlap, the Atlas should make the overlap visible rather than assign all authority to one side.

```text
OVERLAP ≠ SHARED OWNERSHIP
SIMILAR VOCABULARY ≠ SAME DOMAIN
CROSS-LINK ≠ AUTHORITY TRANSFER
```
